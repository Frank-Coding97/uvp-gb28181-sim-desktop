# 功能规格:录像中心（缩略图与时间筛选）

**状态:已交付(M7)** · 覆盖 FR-51 · 实现见 `apps/desktop`（Recordings.vue / recording-filter.mjs）+ `crates/media-rtp`（thumbnail.rs）+ `apps/desktop/src-tauri`（`get_recording_thumbnail`）。

---

## 1. 目标

录像列表此前只有「时间 + 大小 + 文件名」，两个问题：

1. **看不出内容**：一堆 `2026-10-03 14:22:01` 分不清哪段是想要的画面，必须逐个点开播放。
2. **筛不出时间段**：只能按类型和关键字筛，想找"昨天下午那段"只能翻。

这一批补上列表行首帧缩略图和时间范围筛选。

## 2. 缩略图

- **不随录像落盘**：开录时未必有可用帧，而且会平白多占一份磁盘。
- 首次请求时用外部 `ffmpeg` 从文件里抽一帧，缓存在数据目录 `recording-thumbs/<id>.jpg`。
- 抽帧参数（`crates/media-rtp/src/thumbnail.rs`）：
  - `-ss` 放在 `-i` **之前**：关键帧级快速定位。放在后面会先解码整段再丢掉，长录像上能差好几秒。
  - `-frames:v 1` 只要一帧；`scale=320:...` 宽度固定 320（列表行高 40 px，2 倍屏够清晰）。
  - 抽帧位置按时长回退：> 1 秒从 `1.0s` 处抽（避开首帧黑屏），≤ 1 秒或时长未知从头抽。
- **缓存复用条件**：缓存文件 mtime ≥ 源文件 mtime。录像被覆盖/重写时必须重新抽，不能拿旧图糊弄。
- **失败不阻塞页面**：找不到 ffmpeg / 文件损坏时命令返回错误，行首显示占位图标并带悬停原因，不重试。
  缩略图是增强项，缺一个可选依赖不该让整页录像列表不可用。
- **串行请求 + 上限 80 段**：抽帧要起子进程，并发只会互相抢 CPU；每段录像只请求一次。

### 为什么返回 base64 而不是文件路径

播放用的是 `convertFileSrc(recordings/...)`，因为 asset 协议作用域只放开了 `$APPDATA/recordings/**/*`。
但数据根目录可能被 `UVP_CONFIG_DIR` 或 local-data 回退挪到作用域外，缩略图放那里会全部加载失败。
缩略图很小（十几 KB），直接返回 `data:image/jpeg;base64,...` 既免去作用域配置，也不受目录回退影响。

## 3. 时间范围筛选

| 选项 | 区间 |
|---|---|
| 全部时间 | 不按时间过滤 |
| 今天 | 本地当天 `[00:00, 次日 00:00)` |
| 近 7 天 / 近 30 天 | `[今天-(N-1) 天 00:00, 次日 00:00)`，**含今天** |
| 自定义 | 两个 `datetime-local` 输入框 |

### 语义：按时间窗重叠命中

判定条件是 `start < to && end > from`，不是"开始时间落在窗内"。

一段 `10-05 20:00 → 10-06 02:00` 的跨夜录像，在「今天」筛选里**必须出现** —— 用户找的是
"今天这段画面"，而不是"今天才开始录的文件"。按开始时间判会把跨夜录像整个藏起来。

由此带来的两个细节：

- 结束时间精确到分钟：填 `12:00` 会额外加 60 秒，因为用户通常期望包含 12:00 这一分钟。
- 起止填反自动交换，不筛出空列表；非法文本按"该侧不限"处理，不让 `NaN` 把列表全滤掉。

## 4. 其它

- 列表行显示时长（`formatDuration`），播放面板也补了「时长」一行。
- 状态条「已完成录像」在筛选生效时显示 `筛选数 / 总数`，避免误以为录像丢了。
- 切到「自定义」时用「今天」预填两个输入框：空框会让人以为筛选坏了。
