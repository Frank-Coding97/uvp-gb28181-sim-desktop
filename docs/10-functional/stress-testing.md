# 功能规格:压力测试

**状态:核心已实现** · 覆盖 FR-20~FR-28 · 核心差异化能力 · 实现见 `30-crates/stress-engine.md`、`scenario.md`。

> 已实现:批量设备生成(FR-20)、爬坡速率(FR-21)、并发注册/心跳(FR-22)、媒体三档 A/B/C(FR-23)、active_ratio 推流采样(FR-24)、TOML 场景保存加载(FR-25)、原子指标+失败归因(FR-26/27)、报告导出(FR-28)、**主动上报施压(批量定位/报警)**。
> **UI**:压测场景编排与运行监控大盘**合并为单页「压力测试」**(FR-41+FR-42),配置在上、启动后同页出实时曲线;C 档可选视频源文件。
> 待补:指标落 SQLite 时序持久化(当前报告仅含最终快照)、TCP 推流。

---

## 1. 目标

用一台(未来多台)机器模拟海量下级设备,量化上级平台的**承载上限、成功率、时延、稳定性**。

## 2. 媒体三档强度(FR-23)

| 档 | 内容 | 压什么 | 单机规模目标 |
|---|---|---|---|
| **A 空媒体** | 只注册/心跳/目录应答,不推流 | 平台 SIP 信令承载 | 万级 |
| **B 轻量 RTP** | 推固定/伪 PS 包,极低码率 | 平台 RTP 端口/会话/带宽调度 | 千级 |
| **C 真实码流** | 循环推真实 H.264/H.265 | 实战级带宽 + 解码承载 | 百级(受带宽限) |

`active_ratio` 控制真推流设备占比(FR-24),其余仅维持信令 —— 用少量真实流 + 大量信令,逼近真实部署形态。

## 3. 场景模型(FR-25)

TOML 定义(字段平铺在顶层,无 `scenario:` 包裹),对应 `30-crates/scenario.md` 的 `LinearScenario` 结构。示例见 `examples/scenarios/linear.toml`。关键字段:

- `base_device_id` — 起始 20 位 ID(后续 u128 递增),`password`(批量生成规则,FR-20)
- `server_host`/`server_port`/`server_domain` — 上级平台
- `ramp_per_second` — 爬坡速率(每秒拉起台数,0=一次全拉起,FR-21)
- `heartbeat_interval_secs` — 心跳间隔;`channels_per_device` — 每设备通道数
- `media_profile`(A/B/C)+ `active_ratio` + `bitrate_kbps` + `video_source` + `video_fps`(FR-23/24)
- `gb_version`(2016/2022)、`transport`(UDP/TCP)

## 4. 调度策略

### 4.1 爬坡启动(FR-21)
按 `ramp_per_second` 分批创建设备并发起注册,避免瞬时注册风暴打死平台或本机。例:5000 台 @ 100/s → 50s 内均匀拉起。

### 4.2 并发承载(FR-22)
- 每台设备是**轻量异步任务**(Tokio task),非独立线程。
- 心跳/重注册用**时间轮 / 分桶定时器**,万级设备不产生 sleep 惊群。
- SIP 收发共享 socket + 事务路由,避免端口耗尽。

### 4.3 推流采样(FR-24)
按 `active_ratio` 随机抽取设备子集,仅这些真推流(档 B/C),其余只维持信令。

### 4.4 主动上报施压(设备 → 平台)
除注册/心跳/推流外,可让每台设备**周期主动上报**定位(MobilePosition NOTIFY)与报警(Alarm),
模拟真实设备的上行业务对平台施压。UI 开关 + 间隔(秒),引擎侧 `Orchestrator::run(position_secs, alarm_secs)`
为每设备挂周期任务(0=关),成功数计入 `position_reported`/`alarm_reported` 指标。

## 5. 指标采集(FR-26、FR-27)

引擎每秒聚合无锁原子指标,经 **Tauri 事件 `metrics_tick`** 推 UI(见 `20-architecture/api-contract.md`)。时序落 SQLite 为规划中;当前报告导出为最终快照 JSON(见 `20-architecture/data-model.md`)。

| 指标 | 说明 |
|---|---|
| 注册尝试 / 成功 / 成功率 | 累计与瞬时 |
| 注册时延 | 分位数(p50/p95/p99) |
| 心跳成功率 | 周期成功比 |
| INVITE 成功率 / 建流时延 | 点播场景 |
| 活跃推流路数 | 当前真推流数 |
| 总发送码率 / 包速率 | Mbps / pps |
| 失败归因 Top-N | 超时 / 认证失败 / 平台拒绝(4xx/5xx) / 网络错误 |

指标热路径用原子计数 + 无锁聚合(NFR-4),不在每包路径加锁。

## 6. 压测报告(FR-28)

结束后导出:场景参数、指标时间序列(可绘曲线)、失败明细、环境信息。格式先 JSON,UI 侧渲染;后续可加 HTML/CSV。

## 7. 安全边界(NFR-9)

压测流量大、破坏性强,**仅限受控内网/测试环境**;严禁对公网或未授权平台施压。UI 应在启动大规模压测前二次确认。

## 8. 验收

- 空媒体档单机 5000 台稳定注册+心跳 ≥30min,无内存泄漏(NFR-3/4)。
- 监控大盘实时显示成功率曲线与失败归因(FR-26/27)。
- 场景可保存加载复跑(FR-25)。
