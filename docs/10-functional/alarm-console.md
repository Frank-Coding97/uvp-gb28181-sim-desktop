# 功能规格:报警单管理

**状态:已交付(M7)** · 覆盖 FR-9 · 实现见 `apps/desktop`(Alarms.vue)+ `crates/gb28181-protocol/src/alarm.rs` + `crates/gb28181-simulator/src/device.rs`。

---

## 1. 目标

联调报警业务时，现场需要的不只是"点一下发条报警"，而是**能定制的报警单 + 能回看的发送记录**：平台为什么没收到、当时发的什么级别/方式、走的是订阅还是独立 MESSAGE，这些必须在界面上直接看到，而不是回翻 SIP 报文。

## 2. 报警单字段

| 字段 | 取值 | 说明 |
|---|---|---|
| AlarmPriority | 1-4 | 1 最高 |
| AlarmMethod | 1-7 | 电话/设备/短信/GPS/视频/器件/人工 |
| AlarmType | 1-5 或留空 | 1 视频丢失 / 2 设备防拆 / 3 存储满 / 4 设备故障 / 5 其他；留空则整段 `<Info>` 不输出 |
| AlarmDescription | 文本 | 可空 |
| Longitude / Latitude | −180~180 / −90~90 | 可空；以字符串进 XML，最多 6 位小数并去尾零 |
| AlarmTime | 现在 / 5·15·30·60 分钟前 | **只改时间戳，不延迟发送** |

预检在协议层 `AlarmReport::validate` 完成：非法取值在组装 XML 前就被拒绝，不会发出半成品报文。

## 3. 交互

- **固定单**：视频丢失 / 设备防拆 / 存储满 / 设备故障 / 人工触发，一键填表，保留当前经纬度与时间偏移。
- **随机发一条**：模板、等级、时间偏移随机，用于验证平台对不同取值的处理。
- **XML 预览**：调用 `preview_alarm_xml`，与实际发送共用 `to_notify`，SN 固定为 1（真实发送用递增序列号）。
- **发送**：设备未启动时按钮禁用；发送结果提示平台应答码与发送路径。
- **复位本机报警**：只清设备本地 `alarming` 标记（下一次 DeviceStatus 回到"无报警"），不向平台补发报文。
- **历史**：最近 50 条，最新在前；每条显示落库时间、送达状态、发送路径（订阅 NOTIFY / 独立 MESSAGE）、等级方式、描述、报文里的 AlarmTime、类型与经纬度、失败原因。

## 4. 发送路径

| 条件 | 路径 |
|---|---|
| 平台已建立 Event:Alarm 订阅对话 | 对话内 SIP NOTIFY（GB28181 订阅语义），并累加 `Alarm` 订阅通知计数 |
| 未订阅 / 手动触发 | 独立 MESSAGE（新 Call-ID） |

两条路径共用同一段报文组装逻辑，避免"订阅时发的和手动发的不是同一个报文"。

## 5. 验收

- 设备注册后选「设备防拆」→ 发送 → 平台侧报警列表出现 `AlarmMethod=2 / AlarmType=2` 的报警，界面历史显示 `应答 200` 与发送路径。
- 清空 AlarmType 后发送 → 预览 XML 中不存在 `<Info>`。
- 选择「30 分钟前」发送 → 报文 `AlarmTime` 比当前时间早 30 分钟，且发送动作立即完成。
- 设备停止后发送 → 按钮禁用；绕过前端直接调命令 → 返回「设备未启动」，历史不新增。
- 拨号失败场景（平台不可达）→ 历史新增一条 `失败` 记录并带错误原因，而不是只弹一次 toast。
