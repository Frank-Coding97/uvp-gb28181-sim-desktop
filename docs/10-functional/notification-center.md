# 功能规格:通知中心

**状态:已交付(M7)** · 覆盖 FR-52 · 实现见 `apps/desktop`（notification-center.ts / notifications.mjs / components/NotificationBell.vue）+ `App.vue`（顶栏挂载）。

---

## 1. 目标

平台侧的动作散落在各页面：订阅建立提示在首页卡片上，平台控制提示在首页时间线里，
设备注册失败在顶栏错误条里，语音广播在采集页。**切到别的页面就看不到**。

通知中心把这些"用户需要知道的事"收进顶栏一个铃铛，跨页面可见、有未读计数、能回看。

## 2. 什么进通知，什么不进

| 进通知 | 来源事件 |
|---|---|
| 设备状态翻转（已注册 / 注册失败 / 已断开 / 平台开始点播） | `device_state` |
| 采集与运行时错误 | `device_error` |
| 平台下发命令（摘要即标题，`kind` 命中 error/fail/reject 时定级为错误） | `platform_command` |
| 订阅建立 / 退订 | `subscription_state` |
| 语音广播开始 / 结束 | `broadcast_state` |

| 不进通知 | 原因 |
|---|---|
| `sip_trace` | 结构化报文流水，属于日志页；进通知会被刷爆 |
| `metrics_tick` | 1 Hz 指标，属于看板 |
| 位置订阅每次上报 | 每 5 秒一条，`subscription_state` 会带计数重复到达 |
| 设备 `Registering` 中间态 | 每次重连都刷一条，没有信息量 |
| 录像/抓拍/导出的成功提示 | 已由各自页面就地 toast，二次进通知只是噪音 |

## 3. 订阅只在状态翻转时提示

`subscription_state` 事件在**每次通知上报后**都会到达（用来更新计数）。若按事件逐个提示，
位置订阅会每 5 秒产生一条通知。

因此按 `kind` 记住上一次的 `active`，只有翻转才产生通知：

- `false → true`：`目录订阅已建立`（success）
- `true → false`：`目录订阅已退订`（warning）
- 相同：无通知

这份状态原本只在首页卡片里维护，通知中心维护自己的一份 —— 它要能在任何页面工作，
不能依赖某个页面组件是否挂载。

## 4. 列表行为

- 最多 **50 条**，最新在最前，超出丢最旧的。
- `id` 单调递增而**不复用下标**：列表头部插入会让下标整体偏移，用下标当 key 会让抽屉里的行错位。
- 追加返回**新数组**，不原地改 → Vue 能正确触发更新，单测也能断言"原数组未被修改"。
- 标题为空的通知直接丢弃：列表里出现空行比不出现更糟。
- 打开抽屉即全部置读；单条可点读；支持清空。相对时间每分钟刷新一次（`刚刚 / N 分钟前 / N 小时前 / N 天前`），不每秒重渲染列表。
- 时钟回拨导致时间戳在未来时显示「刚刚」，不显示负数。

## 5. 生命周期

事件订阅挂在应用壳（`App.vue`）上，用 `startNotificationCenter()` / `stopNotificationCenter()` 管理：
与当前停在哪个页面无关，切页不丢历史；重复调用是安全的（已有监听时直接返回停止函数）。

非 Tauri 环境（浏览器直接打开构建产物）下不注册订阅，铃铛仍在但列表为空。
