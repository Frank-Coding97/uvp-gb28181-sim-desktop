# 功能规格:定时录像计划

**状态:已交付(M7)** · 覆盖 FR-48 · 实现见 `apps/desktop`(RecordPlan.vue / record-plan.mjs)+ `crates/record-plan` + `apps/desktop/src-tauri`(调度器)。

---

## 1. 目标

让桌面端产出的录像不只是"手动点一下"，而是**按周时间表自动录制**：联调平台的回放、下载、录像查询时，需要真实的定时录像文件，且时间对得上。

## 2. 计划模型

- 一周 7 天（周一在前），每天若干时段，**每天最多 8 段**。
- 时段左闭右开 `[start_sec, end_sec)`，秒为一天内偏移，`end_sec` 最大 86400（可写 24:00:00）。
- **相邻段自动合并**：连点两格 08:00-08:30 与 08:30-09:00 会变成一段 08:00-09:00，而不是两段。
- 归一化（排序 → 裁剪到当天 → 合并重叠/相邻）在保存时由后端再做一次，前端只是让界面自洽。
- 默认 **关闭**：旧配置升级上来不会突然开始自动录像。

## 3. 交互

| 区域 | 行为 |
|---|---|
| 总开关 | 关闭时即使画了时段也不录像（`plan_effective = enabled && 有时段`） |
| 周选择 | 周一..周日切换，今天带「今」标记，默认落在今天 |
| 30 分钟网格 | 48 格；点击涂上/擦掉该格；虚线分隔 1 小时边界；当前时刻所在格高亮 |
| 时段列表 | 每段可改起止（`HH:MM` 或 `HH:MM:SS`）；非法或倒流的时间被拒绝并提示；可删除、清空当天、复制到全周 |
| 状态面板 | 设备/调度任务是否运行、当前录像阶段、此刻是否在时段内、本机周几与时间、今日计划迷你图 |
| 保存 | 有未保存改动才可保存；保存后运行中的设备立即生效 |

## 4. 调度

- 设备启动时以**配置文件**为准把计划灌入内存共享状态，然后启动调度任务。
- 每 **10 秒**判定一次：`enabled && week.should_record(weekday, secs)`。
- 进入时段且当前 `Idle` → `start_recording(Time, Local)`，录像来源标记为「定时」。
- 离开时段且当前录像**是本任务起的** → 停止。
- 手动录像不受影响：调度任务只停自己起的录像（`plan_owned` 标记在任务内维护）。
- 设备停止：**先取消调度**，再收尾录像 —— 否则任务可能在收尾后把录像又起起来。
- 启动失败（媒体未就绪等）只记 warning，下一轮继续尝试，不让任务退出。

## 5. ConfigDownload 回读

平台查询 `VideoRecordPlan` 时，`RecordPlanType` 随实际生效状态切换：

| 状态 | RecordPlanType |
|---|---|
| 开关打开且至少有一段 | 0（定时录像） |
| 关闭或没有任何时段 | 2（无生效的定时计划） |

设备启动与每次保存都会同步这个值，避免"平台看到定时计划，设备其实不录"。

## 6. 验收

- 把周一 08:00-08:30 涂上 → 时段列表出现 `08:00:00 → 08:30:00`，再点 08:30 格合并为 `08:00:00 → 09:00:00`。
- 手工把开始时间改成 09:00（晚于结束 08:30）→ 提示"结束时间必须晚于开始时间"，草稿不变。
- 保存后设备运行中：把当前时刻所在格涂上 → 10 秒内开始录像，录像中心出现来源为「定时」的记录；擦掉该格 → 10 秒内停止并收尾。
- 手动在录像中心点「开始录像」→ 时段结束时计划不会把它停掉。
- 关闭总开关 → 平台查 `VideoRecordPlan` 返回 `RecordPlanType=2`；打开并保留时段 → 返回 0。
- 超过 8 段保存 → 返回「周X最多 8 段」错误，配置不落盘。
