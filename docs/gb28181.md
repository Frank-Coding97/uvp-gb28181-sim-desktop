# GB28181 使用说明与压测设计

本项目实现 GB/T 28181-2022 下级设备（IPC）侧协议。协议流程参考开源项目 uvp-gb28181-sim（Android 版），桌面端独立用 Rust 重写。

## 2. 关键 ID 编码

GB28181 设备/通道 ID 为 20 位：`中心编码(8) + 行业(2) + 类型(3) + 序号(7)`。批量生成虚拟设备时按序号递增，见 `gb28181-protocol::IdCodec`。

## 3. 压测设计

压测是本项目的差异化能力。目标：用一台（或多台）机器模拟海量下级设备，测量上级平台的承载上限、成功率、时延。

### 3.1 三档媒体强度

| 档位 | 内容 | 用途 |
|---|---|---|
| **A 空媒体** | 只注册 / 心跳 / 目录应答，不推流 | 测平台 SIP 信令承载（最高并发） |
| **B 轻量 RTP** | 推固定/伪 PS 包，低码率 | 测平台 RTP 端口、会话、带宽承载 |
| **C 真实码流** | 循环推真实 H.264/H.265 文件 | 实战级承载与解码压力 |

### 3.2 场景模型（YAML）

```yaml
scenario:
  name: "5000-device-register-test"
  platform:
    host: "192.168.1.100"
    port: 5060
    domain: "34020000002000000001"
  devices:
    count: 5000
    id_prefix: "34020000001320000"   # 后 7 位按序号递增
    start_index: 1
    password: "12345678"
  register:
    enabled: true
    rate_per_second: 100              # 每秒拉起 100 台，避免瞬时风暴
  heartbeat:
    enabled: true
    interval_seconds: 60
  media:
    enabled: true
    mode: "real"                      # none | light | real
    active_ratio: 0.1                 # 仅 10% 设备真推流
    bitrate_kbps: 512
    file: "./assets/media/test.h264"
  duration_seconds: 1800
```

### 3.3 调度策略

- **爬坡启动**：按 `rate_per_second` 分批创建设备，避免瞬时 SYN/注册风暴打死平台。
- **定时器分桶**：心跳/重注册用时间轮，万级设备不产生惊群。
- **推流采样**：按 `active_ratio` 抽取子集真推流，其余只维持信令。

### 3.4 采集指标

注册成功率/时延、心跳成功率、INVITE 成功率/建流时延、活跃推流路数、总发送码率/包速率、失败原因 Top-N（超时/认证失败/拒绝/网络错误）。指标每秒聚合并经 WebSocket 推 UI，同时落 SQLite 供压测报告导出。

## 4. 联调平台（WVP-Pro 示例）

```bash
docker run -d --name wvp \
  -p 18080:18080 -p 5060:5060/udp -p 30000-30500:30000-30500 \
  648540858/wvp_pro:latest
# 控制台 http://localhost:18080 (admin/admin)
```

单设备联调：设备 ID `34020000001320000001`、平台 ID `34020000002000000001`、服务地址 `WVP主机:5060`，密码与 WVP「国标设备」配置一致。

## 5. 安全边界

GB28181 默认明文传输、Digest 用 MD5。**压测尤其只在受控内网/测试环境进行**，勿对公网或未授权平台施压。
